## [Unreleased]

### Fixed（v2.7，2026-11）

- **`alipay.py` v1.2**：detect 从 `or "支付宝"` 改为严格三条件
  - 原因：赣州 PDF 含"支付宝信贷业务"字样被误命中，自动检测失败
  - 影响：所有含"支付宝"字样的非支付宝 PDF
  - 教训：→ README 3.2 禁止 3 + 坑 8（`or` 反模式）

- **`nongye.py` v18.4**：删除 `_deduplicate` + 补字段 + detect 严格化
  - 原因：去重违反 README 3.2 禁止 1；`交易方向`/`交易分类` 算了没返回；detect 用 `or "农业银行"` 宽泛条件
  - 影响：农行同日多笔"短信费 -2"不再误杀；`交易方向`/`交易分类` 列不再空；不再误命中其他含"农业银行"的 PDF
  - 教训：→ README 3.2 禁止 1、禁止 3、禁止 4

- **`ccb.py` v13.3**：detect 严格化 + `_classify` 补"提现" + `<1` 阈值
  - 原因：detect 单特征 `"建设银行"` 太宽；"支付机构提现"被误归"其他"；`<5` 阈值对小 PDF 会误触发坐标回退
  - 影响：建行流水解析更稳定；"支付机构提现"正确归"存取现"
  - 教训：→ README 3.2 禁止 3

- **`ganzhou.py`**：`_is_wide_char` 精确 CJK 判断
  - 原因：`ord(ch) > 127` 会漏判全角标点，导致"南昌大学第二附 属医院"中间多空格
  - 影响：跨行拼接中文时不再误加空格
  - 教训：→ README 坑 3
