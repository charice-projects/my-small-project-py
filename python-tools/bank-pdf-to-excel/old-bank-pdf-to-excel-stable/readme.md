## 一、项目概述

### 1.1 一句话介绍

把银行/支付平台的 PDF 流水文件，转换为结构化、可分析、可归档的 Excel 表格。

### 1.2 已支持的平台

| 插件 | 状态 | 解析策略 | 适用 PDF 特征 |
|------|------|---------|--------------|
| 农业银行 | ✅ 生产稳定 | 坐标聚类（逐行解析） | 无边框、列位置固定的文本表格 |
| 招商银行 | ✅ 生产稳定 | 行文本正则 | 流式文本，无固定列 |
| 交通银行 | ✅ 生产稳定 | 表格提取（16 列·借贷双列） | `extract_tables()` 完美，空列保留 |
| 建设银行 | ✅ 生产稳定 | 表格提取（7 列·单列带符号） | `extract_tables()` 完美，序号 1~893 连续 |
| 微信支付 | ✅ 生产稳定 | 表格提取 + OCR 降级 | 标准表格 / 扫描件 |
| 支付宝 | ✅ 生产稳定 | 表格提取 + 文本回退 | 标准表格 |
| 赣州银行 | ✅ 生产稳定 | 坐标聚类（锚点法） | 无边框、列固定、**单笔交易跨多行** |
| 通用后备 | ✅ 兜底 | 坐标解析 + 列嗅探 | 未知格式 |

> 💡 **"坐标聚类"有两种变体**：农行是"逐行解析"（一行 = 一笔），赣州是"锚点法"（一笔跨多行）。新银行 PDF 先判断是否跨行，再选变体。详见 [7.9 坐标聚类的两大变体](#79-坐标聚类的两大变体重要)。

### 1.3 核心设计原则

- **插件隔离**：每个银行/平台独立成文件，互不干扰，新增插件不影响已有插件
- **策略精准**：针对不同 PDF 布局选择最优解析方式（不搞一招鲜）
- **降级保障**：主解析失败自动回退到备选方案
- **进度反馈**：全流程 tqdm 进度条，大文件无压力
- **批量支持**：`batch.py` 支持目录级批量处理，自动检测插件、独立输出
- **AI 友好**：项目结构、字段命名、README 都遵循可被 AI 快速理解的原则

### 1.4 技术栈

- **PDF 解析**：`pdfplumber`（主）+ `pypdf`（降级）
- **坐标聚类**：`scikit-learn` 的 `DBSCAN`
- **数据处理**：`pandas` + `numpy`
- **Excel 输出**：`openpyxl`
- **进度条**：`tqdm`
- **OCR（可选）**：`pytesseract` + `pdf2image`

## 二、项目结构

```
bank-pdf-to-excel/
├── main.py                      # 单文件交互式主程序
├── batch.py                     # 批量处理脚本
├── probe.py                     # PDF 结构探测器（新增插件前必跑）
├── requirements.txt             # 依赖清单
├── README.md                    # 本文档
│
├── plugins/                     # 插件目录（每个银行/平台一个文件）
│   ├── __init__.py              # 插件注册中心（新增插件在此登记）
│   ├── base.py                  # 插件抽象基类 (StatementPlugin)
│   ├── nongye.py                # 农业银行 (坐标聚类·逐行)
│   ├── zhaoshang.py             # 招商银行 (行文本正则)
│   ├── jiaotong.py              # 交通银行 (表格提取·16 列借贷双列)
│   ├── ccb.py                   # 建设银行 (表格提取·7 列单列带符号，三级降级)
│   ├── wechat.py                # 微信支付 (表格+OCR)
│   ├── alipay.py                # 支付宝 (表格提取)
│   ├── ganzhou.py               # 赣州银行 (坐标聚类·锚点法)
│   └── universal.py             # 通用后备解析器
│
└── utils/                       # 公共工具库
    ├── helpers.py               # 通用工具函数
    └── parser_common.py         # 公共解析基类 + 坐标引擎
```

### 2.1 关键文件职责

| 文件 | 职责 | 何时修改 |
|------|------|---------|
| `main.py` | 单文件交互式入口 | 仅在改交互流程时 |
| `batch.py` | 批量处理入口 | 仅在改批量逻辑时 |
| `probe.py` | PDF 结构探测脚本 | 新增银行插件前先跑，判断策略 |
| `plugins/__init__.py` | 插件注册与优先级 | **每次新增插件都要改** |
| `plugins/base.py` | 插件接口定义 | 只在改接口时（几乎不动） |
| `plugins/xxx.py` | 单个银行解析逻辑 | **新增银行时新建** |
| `utils/parser_common.py` | 基类 + 坐标引擎 | 只在改基础能力时（很少动） |
| `utils/helpers.py` | 文本清洗、数值转换 | 只在改基础工具时（很少动） |

### 2.2 数据流

```
用户输入 PDF 路径
    ↓
main.py / batch.py
    ↓
循环 PLUGINS 列表，调用 plugin.detect(pdf_path)
    ↓
命中插件 → plugin.parse(pdf_path) → (account_info, transactions)
    ↓
pandas DataFrame → Excel（4 个 Sheet）
    ↓
可信度报告（txt）+ 批量汇总（csv，仅批量模式）
```

## 五、批量处理（重点）

> **批量处理是本工具处理"一个月几十份流水"场景的核心能力。** 本节详细说明。

### 5.1 基本用法

```bash
# 1. 处理整个目录（一 PDF 一 Excel，全部自动检测）
python batch.py "D:/流水/2025-10"

# 2. 指定输出目录
python batch.py "D:/流水/2025-10" -o "D:/流水/输出"

# 3. 只处理文件名匹配的 PDF
python batch.py "D:/流水/2025-10" -p "农业*"

# 4. 处理单个 PDF（无需交互，便于脚本集成）
python batch.py "D:/流水/交通银行.pdf"

# 5. 显示详细日志（调试用）
python batch.py "D:/流水/2025-10" -v
```

### 5.2 参数说明

| 参数 | 简写 | 说明 | 默认 |
|------|------|------|------|
| `input` | — | 输入目录或 PDF 文件路径（必需） | — |
| `--output` | `-o` | 输出目录 | 输入目录（若输入是文件则为其父目录） |
| `--pattern` | `-p` | 文件名通配符（如 `"农业*"`、`"2025-10-*.pdf"`） | 全部 `*.pdf` |
| `--verbose` | `-v` | 显示每个文件的详细解析日志 | 关闭 |

### 5.3 批量处理核心特性

| 特性 | 说明 | 好处 |
|------|------|------|
| **自动检测** | 每个 PDF 独立走 `PLUGINS` 检测流程 | 不同银行混在一个目录也能处理 |
| **兜底机制** | 所有专用插件失败时自动用 `UniversalPlugin` | 未知格式也能试一试 |
| **失败隔离** | 单个文件失败不影响其它文件 | 20 个文件里 1 个坏的不耽误 19 个 |
| **同名保护** | 输出 Excel 已存在时自动加时间戳 | 不会意外覆盖历史结果 |
| **进度条** | 显示总体进度 + 当前文件名 | 大目录（50+文件）不焦虑 |
| **汇总 CSV** | 结束后生成 `_batch_summary_时间戳.csv` | 哪些成功/失败一目了然 |

### 5.8 批量处理后的三个检查点

1. **看成功/失败比**
   - 全成功 → 直接用 Excel
   - 有失败 → 打开汇总 CSV，看 `error` 字段

2. **看是否有"通用兜底"**
   - 若有 PDF 用 `通用后备(兜底)` 解析 → 说明是**新格式**，可能存在字段错位
   - **建议**：把这类 PDF 单独拿出来，我们讨论是否为其新增专用插件

3. **看笔数是否合理**
   - 明显偏少（如只有 3 笔但实际几十笔）→ 表头识别或列映射有问题
   - 明显偏多 → 可能重复计入

## 七、插件解析策略详解

> **本节是核心技术文档**，说明每个插件的策略、适用场景、实现原理。后续遇到同类型银行 PDF 时，可直接参考对应策略开发。

### 7.1 策略对照总览

| PDF 类型 | 解析策略 | 参考插件 | 关键技术 |
|---------|---------|---------|---------|
| 标准表格·**借贷双列**（空列保留） | 表格提取 | **交通银行** | `extract_tables()` + 借方/贷方判断 |
| 标准表格·**单列带符号** | 表格提取 | **建设银行** | `extract_tables()` + `safe_float` 判正负 |
| 固定列宽文本（无边框）·逐行 | 坐标聚类·逐行 | 农业银行 | DBSCAN 分列 + 行分组 |
| 流式文本（无固定列） | 行文本正则 | 招商银行 | 正则提取 + 对手信息分离 |
| 标准表格（有边框） | 表格提取 | 微信/支付宝 | `extract_tables()` |
| 扫描件/图片 PDF | OCR 降级 | 微信支付 | Tesseract OCR |
| 无边框、列固定、**单笔跨多行** | 坐标聚类·锚点法 | **赣州银行** | 日期词作锚点 + 最近锚点归属 |
| 未知格式 | 通用兜底 | universal.py | 坐标解析 + 列嗅探 |

### 7.2 交通银行插件（`jiaotong.py`）— 表格提取·16 列借贷双列

**适用场景**：交通银行对公账户明细对账单，PDF 有表格边框，`extract_tables()` 完美识别且**空列保留为 `''`**（不压缩）。

**16 列固定结构**：

```
序号 | 会计日期 | 交易日期 | 交易名称 | 凭证种类 | 凭证号码
| 借方发生额 | 贷方发生额 | 余额 | 卡号 | 交易地点
| 对方账号 | 对方户名 | 对方行名 | 摘要 | 流水号
```

**核心逻辑**：

| 项目 | 规则 |
|------|------|
| **交易方向** | 借方有值 → 支出；贷方有值 → 收入 |
| **交易金额** | 支出取负，收入取正 |
| **表头识别** | 检查 `['序号','会计日期','借方发生额','贷方发生额','余额']` 是否全部出现 |
| **多页表头** | 自动跳过（序号列非数字的行被过滤） |
| **单元格换行** | `\n` 合并为空格（如 `超级网银来账\n贷记-对公` → `超级网银来账 贷记-对公`） |

**回归校验**：交通银行对账单末尾有"本月累计借方/贷方发生额"，可用于验证解析完整性。

### 7.3 农业银行插件（`nongye.py`）— 坐标聚类·逐行

**适用场景**：文本型表格，**无表格边框线**，列位置相对固定，且一笔交易的字段**在同一条水平线上**。

**核心流程**：

```
PDF 页面
    ↓
page.extract_words()  ← 提取单词坐标
    ↓
1. _determine_columns: DBSCAN 聚类表头词 X 坐标 → 列边界
2. _group_lines: DBSCAN 聚类单词 Y 坐标 → 行分组
3. _parse_line: 按列边界分配单词 → 提取字段
    ↓
交易列表
```

**关键方法**：

- `_find_header_line`：找包含 `["交易日期", "金额"]` 的行
- `_determine_columns`：优先用表头词 X 坐标聚类，失败则全局聚类
- `_group_lines`：eps 根据页面 y 间距中位数动态计算

### 7.4 招商银行插件（`zhaoshang.py`）— 行文本正则

**适用场景**：**流式文本**，无固定列宽。数据行格式：`日期 CNY 金额 余额 摘要 对手信息`。

**核心流程**：

```
page.extract_text() → 逐行处理
    ↓
1. 正则提取日期 (YYYY-MM-DD)
2. 正则提取金额 + 余额 (CNY 后面跟两个数字)
3. 剩余文本 → 摘要 + 对手信息分离
    ↓
交易列表
```

**对手信息分离策略（按优先级）**：

1. 非人名关键词（如"美团平台商户"）— 需维护 `COUNTERPARTY_KEYWORDS` 列表
2. URL（`https?://...`）
3. 中文名（2~30字符）+ 账号
4. 纯中文名
5. 纯账号（10~20 位数字）
6. "微信转账" 等特定模式

**对手信息分离示例**：

| 原始文本 | 摘要 | 对手信息 |
|---------|------|---------|
| `快捷支付 美团平台商户 246494750` | 快捷支付 | 美团平台商户 246494750 |
| `银联快捷支付 江西九江科技中等专业学校 2088...` | 银联快捷支付 | 江西九江科技中等专业学校 2088... |
| `快捷支付 https://www.apple.com/... 1481605881` | 快捷支付 | https://www.apple.com/... 1481605881 |

### 7.5 微信支付插件（`wechat.py`）— 表格 + OCR 三级降级

```
主解析: extract_tables()
    ↓ 失败/空
文本回退: parse_from_text_fallback()
    ↓ 若 raw_text < 100 字符
OCR 降级: Tesseract（需手动安装）
```

### 7.6 支付宝插件（`alipay.py`）— 表格 + 文本回退

与微信类似，但无 OCR 降级。表头关键词：`交易时间`、`交易对方`、`金额`。

### 7.7 建设银行插件（`ccb.py`）— 表格提取·7 列单列带符号（三级降级）

**适用场景**：中国建设银行个人活期账户全部交易明细，PDF 有表格边框。

**7 列固定结构**：

```
序号 | 摘要 | 交易日期 | 交易金额 | 账户余额 | 交易地点/附言 | 对方账号与户名
```

**核心逻辑**：

| 项目 | 规则 |
|------|------|
| **交易方向** | 金额单列带符号：`+8000.00` → 收入；`-0.01` → 支出 |
| **交易金额** | `safe_float` 直接解析（含正负号） |
| **表头识别** | `"交易日期"` + `"金额"` 同时出现 |
| **对方信息** | `账号/户名` 用 `/` 拼接（未拆分，保留原样） |
| **附言** | `***` 隐私掩码原样保留 |

**三级降级机制**：

```
1. _parse_by_tables()          ← 主路径（本次 PDF 命中此路径）
    ↓ 行数 < 5
2. _parse_by_coordinates()     ← 坐标解析
    ↓ 行数 < 5
3. _parse_from_text_lines()    ← 文本行分割（最后兜底）
```

**⚠️ 不做去重**（v13.2 起）：三级降级互斥执行，本来不会产生重复；且建行存在"日期、摘要、金额、余额、对手**5 字段全同**"的合法独立交易（如序号 499 和 501 的两笔 -320.00/余额 41,192.99），任何按内容指纹的去重都会误杀。详见 [8.7 去重铁律](#87-去重铁律所有插件通用)。

**回归校验**：PDF 首行有"总支出：4,254,660.40；总收入：4,271,557.22"，可用于验证解析完整性。

### 7.8 赣州银行插件（`ganzhou.py`）— 坐标聚类·锚点法

**适用场景**：无表格边框、有文字层、列位置固定，**且一笔交易会跨多行**（对手信息、余额被换行拆分）。

**PDF 特征**：

- 8 列固定：`交易日期 | 币种 | 交易金额 | 余额 | 交易摘要 | 对手信息 | 收单机构 | 收支类型`
- 每页重复表头
- 表头 `收支类型` 被 PDF 拆成 `收支类` + `型` 两行
- 一笔交易的数据会垂直溢出到上下行（如"综合收单待清算"占 2 行、"余额 8321.38" 被拆成 `8321.3` + `8`）

**核心流程**：

```
page.extract_words()
    ↓
1. _detect_columns: 用表头词的 x0 确定 8 列边界（比 DBSCAN 更稳，因为表头词就在那）
2. _find_date_anchors: 日期列里匹配 YYYY-MM-DD 的词 → 交易锚点（一笔一个）
3. _group_by_anchor: 每个词按"最近锚点"归属（距离相等时优先上方）
4. _parse_bucket: 每列内按 y 排序拼接
    ├─ 余额列：直接拼（8321.3 + 8 → 8321.38）
    └─ 其他列：中文相邻不加空格（南昌大学第二附 + 属医院 → 南昌大学第二附属医院）
```

**关键点：为什么"距离相等时优先上方"？**

样例：

```
top=190.2  综合收单待清算          ← 溢出行（视觉上属于 2025-11-04 这笔）
top=194.7  8321.3                ← 溢出行
top=199.2  2025-11-04  +8000.00  ← 锚点（y=199.2）
top=203.7  00079                 ← 溢出行（到上一锚点/下一锚点距离均为 4.5，对称）
```

`8321.3`（top=194.7）到锚点 199.2 的距离 = 4.5，归到本笔 ✅。
`00079`（top=203.7）到本笔锚点距离 = 4.5，到下一笔锚点距离 = 4.5，**相等**。此时若优先下方，会被错分到下一笔；**优先上方**则正确归到本笔 ✅。

**分类特化**：

```python
if "短信费" in combined:           return "手续费"
if "利息结息" in combined:         return "利息"
if "收单清算资金" in combined:     return "转账"
if "信贷" in combined:             return "其他"   # 支付宝/微众信贷还款
```

> 💡 **实现提示**：`ganzhou.py` **不继承 `BasePDFParser`**，因为锚点法需要逐页直接调 `extract_words`（基类的 `load_pdf` 会把整份 PDF 文本拼成字符串，反而对坐标解析没帮助）。**若你的锚点法插件也用不上基类方法，可以像 ganzhou.py 一样纯 Python 实现**——功能正确比"形式上遵循 8.1 骨架"更重要。

### 7.9 坐标聚类的两大变体（重要）

| 变体 | 代表插件 | 行 = 一笔？ | 核心方法 | 何时用 |
|------|---------|-----------|---------|--------|
| **逐行解析** | 农行 | ✅ 是 | `_group_lines` 按 y 聚行 → 逐行解析 | 一笔交易的字段**在同一条水平线上** |
| **锚点法** | 赣州 | ❌ 可能跨多行 | 日期词作锚点 → 最近锚点归属 | 一笔交易的字段**会垂直溢出**（对手信息换行、余额被拆行） |

**判断方法：两轴判断（不能只看行间距）**

**轴 1：基础行布局**（`probe.py`【4】段）
- 行间距稳定 10~25 → 基础布局是"逐行"（大多数银行）
- 行间距 < 10 → 数据全混在一起，直接上锚点法
- 行间距 > 25 → 有空行/跨页，人工确认

**轴 2：单笔交易是否跨行**（`probe.py --full` 看【5】段）
- 一笔交易的多个词 top 极差 > 8 → 跨行溢出，**必须锚点法**
- 一笔交易的多个词 top 极差 ≤ 8 → 单行完整，**逐行解析即可**

**组合判断表**：

| 轴 1（行间距） | 轴 2（单笔跨行） | 策略 | 代表 |
|---------------|-----------------|------|------|
| 10~25 | ≤ 8 | 逐行解析 | 农业银行 |
| 10~25 | **> 8** | **锚点法** | **赣州银行**（行距 20，单笔跨 4~5 行） |
| < 10 | — | 锚点法兜底 | 极端情况 |

> ⚠️ 注意：赣州的**行间距是稳定的 19~20**，跨行问题不在"行间距小"，而在"**一笔交易的字段垂直溢出到锚点上下**"。所以"行间距稳定"不能直接推"逐行解析"，还要看轴 2。

**锚点法的三个必做项**（缺一不可）：

1. **日期锚点**：日期词必须用严格正则 `^\d{4}-\d{2}-\d{2}$` 匹配，避免误命中摘要里的数字
2. **距离相等优先上方**：`if dist < best_dist`（**不是** `<=`），是解决垂直溢出归属的关键
3. **列内拼接分类型**：余额列直接拼、中文列相邻不加空格、其他列加空格

## 七点五、PDF 探测脚本 probe.py（新增插件前必跑）

> **本节专为 AI 协作设计**。因为 AI 对话里通常无法直接运行 pdfplumber 解析你上传的 PDF 二进制，所以流程是：**你在本地跑 `probe.py` → 把输出贴给 AI**。

### 7.5.1 基本用法

```bash
# 标准探测（输出 1~6 段，够判断策略）
python probe.py "赣州银行流水.pdf"

# 精确探测（追加首页完整 extract_words，用于定位字段错位）
python probe.py "赣州银行流水.pdf" --full

# 多页文本（默认 2 页，大文件可加）
python probe.py "赣州银行流水.pdf" --pages 3
```

> 💡 **路径支持 Git Bash 拖拽**（v1.1 起）：从 Git Bash 拖拽 `/d/流水/file.pdf` 格式的路径，`probe.py` 会自动规范化为 `D:/流水/file.pdf`。**路径含空格时必须加引号**（这是 shell 的硬规则，`main.py`、`batch.py` 同理）。省略引号会被拆成多个参数，`probe.py` 会给出明确提示。

### 7.5.2 输出结构（每段的作用）

| 段落 | 内容 | 给 AI 看什么 |
|------|------|-------------|
| 【1】文本层检查 | 首页文本长度 | 判断是否扫描件（< 30 字符 = 扫描件 → OCR） |
| 【2】extract_tables 测试 | 是否有表格、列数、首表前 3 行 | 有表格 → `jiaotong.py` / `ccb.py` 模板；无 → 坐标聚类 |
| 【3】表头词 + x0 | 疑似表头行所有词的坐标 | 决定列边界、列名映射、判断是否流式文本 |
| 【4】数据区跨行检查 | **识别行数 + 真实行间距中位数 + 间距分布** + 前 20 词 | 轴 1 判断（逐行 vs 混乱），配合【5】做轴 2 |
| 【5】完整 extract_words | 首页全部词（需 `--full`） | 定位单笔交易是否跨行、具体字段错位 |
| 【6】原始文本 | 前 N 页 `extract_text` | 供 AI 看整体版式 |

> 📌 **v1.1 起【4】段的变化**：先 DBSCAN 聚行（eps=5），再算相邻行中心距离。**修复了旧版把"行内 0.3 像素差异"当成"行间距"的 Bug**（旧版建行报 4.0，新版报 20.0）。

### 7.5.3 策略判定决策树

```
probe.py 输出
    ↓
【1】文本 < 30 字符？
    ├─ 是 → OCR（wechat.py 模板）
    └─ 否 ↓
【2】extract_tables 有结果？
    ├─ 是 → 表格提取（jiaotong.py / ccb.py 模板）
    │        ※ 强信号，无需再看【3】【4】
    └─ 否 ↓
【3】表头行有 ≥ 4 个稳定列（x0 差异 < 20 像素）？
    ├─ 否 → 流式文本 → 行文本正则（zhaoshang.py 模板）
    └─ 是 ↓
【4】行间距稳定 10~25？
    ├─ 否（< 10 或 > 25）→ 锚点法兜底（ganzhou.py 模板）
    └─ 是 → 基础布局逐行，继续看轴 2
        ↓（需 probe.py --full 看【5】段）
     单笔交易 top 极差 ≤ 8？
        ├─ 是 → 坐标聚类·逐行（nongye.py 模板）
        └─ 否 → 坐标聚类·锚点法（ganzhou.py 模板）
```

**信号冲突规则**：优先级 `【2】> 【3】> 【4】`。当【2】命中表格时，直接判定表格提取，**忽略【3】【4】**（表格信号最可靠）。

（粘贴）
【3】
（粘贴）
【4】
（粘贴）
【5】（可选，定位字段错位时必须）
（粘贴）

## 八、插件开发完整指南

### 8.1 快速接入新银行：三步法

#### 第一步：分析 PDF 结构（跑 `probe.py`）

```bash
python probe.py "你的路径.pdf"
```

**判断策略**：

| 特征 | 判断 |
|------|------|
| 【1】文本 < 30 字符 | → **参考微信支付**（OCR 降级） |

| 【4】行间距 10~25 但单笔跨行 | → **参考赣州银行**（锚点法） |

### 8.2 解析策略模板对比

| 策略 | 模板文件 | 关键方法 |
|------|---------|---------|
| 表格提取·借贷双列 | `jiaotong.py` | `extract_tables` + 借方/贷方判断 |
| 表格提取·单列带符号 | `ccb.py` | `extract_tables` + `safe_float` 判正负 |
| 坐标聚类·逐行 | `nongye.py` | `_determine_columns`、`_group_lines`、`_parse_line` |
| 坐标聚类·锚点法 | `ganzhou.py` | `_detect_columns`、`_find_date_anchors`、`_group_by_anchor` |
| 行文本正则 | `zhaoshang.py` | `_process_full_line`、`_split_summary_counterparty` |
| 标准表格 | `wechat.py` | `_parse_from_table`、`_extract_from_cells` |

### 8.3 字段映射规范

**必须输出**（核心字段）：

```python
tx = {
    '交易日期': f_date,        # YYYY-MM-DD
    '星期': weekday,          # 英文（Monday 等）
    '摘要': summary,          # 交易摘要
    '交易方向': direction,     # 收入 / 支出 / 其他
    '交易金额': amount,        # 正数=收入，负数=支出
    '对手信息': counterparty,  # 对方名称/账号
    '交易分类': category,      # 见下方分类规范
}
```

**可选输出**（视 PDF 有则填）：

```python
    '账户余额': balance,       # 交易后余额
    '交易时间': time_str,      # HH:MM:SS
```

**特色输出**（各银行自己的字段，随插件定义）：

```python
    '交易名称': trans_name,
    '对方账号': cp_account,
    '流水号': serial,
    # ...
```

> ⚠️ **历史遗留字段名警告**：`nongye.py` 是早期插件，用了非标字段 `交易摘要`（标准是 `摘要`）、`本次余额`（标准是 `账户余额`）。**新插件请遵循上面的标准字段名，不要模仿 nongye 的命名**。Excel 输出时 pandas 会自动按列并集对齐，两种命名不冲突。

**单元格内多字段拼接的 3 种常见处理**：

| 场景 | 处理方式 | 示例 |
|------|---------|------|
| **分列存放** | 拆成多个独立字段 | jiaotong.py：`对方账号` + `对手信息`（户名） + `对方行名` 分 3 列 |
| **合并存放** | 整段字符串作为一个字段 | nongye.py：`对手信息` 包含户名+账号混排 |
| **单元格内拼接** | 按分隔符拆分后分别存放 | ccb.py：`243300133/财付通...` 用 `/` 拆分（可保留整段，或拆成账号+户名） |

> 💡 **建议**：优先拆分成分列。若 PDF 原文是"账号/户名"格式，可参考 jiaotong.py 的 `cp_account` + `cp_name` 分列模式。

### 8.4 交易分类规范

所有插件的 `交易分类` 字段**建议使用以下标准值**：

| 分类 | 触发关键词 |
|------|-----------|
| `消费` | 消费、支付、快捷支付 |
| `转账` | 转账、汇款、代付、转存、转支 |
| `退款` | 退款、退货、冲正 |
| `利息` | 利息、结息 |
| `手续费` | 手续费、管理费、短信费 |
| `工资` | 工资、薪金 |
| `存取现` | 存取现、提现、充值 |
| `大额转账` | 金额 ≥ 50000 且有对手 |
| `其他` | 以上均不匹配 |

### 8.6 开发调试技巧

1. **单文件调试**：`python batch.py "你的.pdf" -v`，加 `-v` 看详细日志
2. **检查解析中间结果**：在解析器中 `print()` 关键中间变量
3. **用表头行做锚点**：`extract_tables` 后先看第一行是不是表头
4. **善用 `detect`**：`detect` 匹配要足够严格，避免误命中其它银行
5. **多页 PDF 重复表头行**：用"序号列非数字则跳过"过滤，**不要用内容去重**
6. **上线前必做**：余额连续性校验（参考 [Q14](#q14-解析结果的总收入总支出与-pdf-汇总不符但抽样核对都没问题怎么办)），确保没有交易被丢

### 8.7 去重铁律（所有插件通用）

**默认不写 `_deduplicate`。** 除非 PDF 明确有"同笔交易跨页重复出现"的证据（如微信支付宝账单的页眉页脚），否则**一行一交易，绝不去重**。

**为什么？** 银行流水天然存在"多个字段完全相同"的合法独立交易：

| 银行 | 案例 | 相同的字段 |
|------|------|-----------|
| 建设银行 | 序号 499 和 501 | 日期 / 摘要 / 金额 / 余额 / 对手，**5 字段全同** |
| 招商银行 | 同日连续快捷支付 | 日期 / 金额 / 摘要 |
| 农业银行 | 同日多笔短信费 | 日期 / 摘要 / 金额 |

**任何按内容指纹的去重都会误杀这些交易。**

**正确做法对照**：

| 需求 | ❌ 错误做法 | ✅ 正确做法 |
|------|------------|-----------|
| 防止重复解析 | `_deduplicate` 按内容指纹 | 三级降级**互斥执行**（`if len < 5` 分支） |
| 防止多页重复表头 | 去重 | 序号列非数字行跳过 |
| 完整性校验 | 去重 | **序号连续性** / **余额连续性**（[Q14](#q14-解析结果的总收入总支出与-pdf-汇总不符但抽样核对都没问题怎么办)） |

**历史教训**：2026-11 建行插件 v13.1 因 `_deduplicate` 误杀 8 笔合法交易（相差 7,920 元），v13.2 删除去重调用后 893 笔与 PDF 完全一致。

## 十、常见问题

### Q1: 解析结果行数不对（偏少或偏多）

**偏少**：

- 检查 `detect` 方法是否正确匹配（如交通银行要求"交通银行"+"明细对账单"同时出现）
- 检查 PDF 是否有多页表头（交通银行已自动跳过：序号非数字的行被过滤）
- 检查 `find_header_row` 关键词是否覆盖

**偏多**：

- 检查是否把"合计"行也计入了交易
- **检查是否有 `_deduplicate` 被滥用**（参考 [8.7 去重铁律](#87-去重铁律所有插件通用)）

### Q2: 对手信息为空

- **招商银行**：检查 `COUNTERPARTY_KEYWORDS` 列表是否包含相关关键词
- **农业银行**：检查列映射中"对手"列的索引是否正确
- **交通银行**：检查表头是否正确定位（16 列顺序固定）
- **赣州银行**：检查锚点法归属是否正确（`probe.py --full` 看【5】段）
- **建设银行**：`对方账号与户名` 列是 `账号/户名` 斜杠拼接格式，若需要拆分，参考 8.3 的"单元格内多字段拼接"

### Q3: 日期解析失败

- 农业银行：`YYYYMMDD`，交通银行：`YYYYMMDD`，招商银行：`YYYY-MM-DD`，赣州银行：`YYYY-MM-DD`，建设银行：`YYYYMMDD`
- 检查 `_parse_date` / `parse_date` 是否覆盖该格式

### Q4: 微信支付 OCR 不工作

1. 确认已 `pip install pytesseract pdf2image`
2. 确认 Tesseract 安装路径正确：
   ```python
   pytesseract.pytesseract.tesseract_cmd = r'C:\Program Files\Tesseract-OCR\tesseract.exe'
   ```
3. 确认已装中文语言包 `chi_sim`

### Q5: 批量处理时文件名冲突？

`batch.py` 检测到同名输出时**自动加时间戳**（如 `农业银行_143022.xlsx`），**不会覆盖**。

### Q6: 批量处理中某个 PDF 失败，会影响其它吗？

**不会**。单个失败会记录到汇总 CSV 的 `error` 字段，其它文件继续处理。

### Q7: 想合并多个 Excel 到一个文件？

目前 `batch.py` 是"一 PDF 一 Excel"。如需合并，可在 `batch.py` 基础上加 `--merge` 参数（多 Sheet 模式）。**建议**：先稳定使用"一 PDF 一 Excel"，需要时再加。

### Q8: 内存不足（大文件）

- 工具已使用逐页处理，但超大 PDF（>100页）可能内存紧张
- 可临时增大 Python 内存限制或分批处理
- 建议：先把大 PDF 拆分为多个月份的小 PDF

### Q9: 怎么确认解析结果正确？

四个回归校验点：

1. **笔数**：与 PDF 里的"总交易笔数"对比
2. **金额合计**：与 PDF 末尾的"累计借方/贷方发生额"对比
3. **余额连续性**：跑 [Q14](#q14-解析结果的总收入总支出与-pdf-汇总不符但抽样核对都没问题怎么办) 校验脚本，0 断点才算完整
4. **可信度报告**：看 `*_report.txt` 是否有 ⚠️ 标记

### Q10: 通用兜底解析结果能直接用吗？

**不能**。通用兜底可能在字段错位上出错（Excel 会打 `⚠️ 通用嗅探解析` 备注）。**建议**：把这类 PDF 单独拿出来，为其编写专用插件。

### Q11: 一笔交易的数据被拆成好几行，怎么办？

**症状**：解析出的交易里，对手信息为空、余额变成 `8321.3` 或 `00079`、摘要串到下一笔。

**原因**：PDF 里这笔交易的数据**垂直溢出**到其它行（对手信息换行、金额分两位）。

**诊断**：跑 `python probe.py "xxx.pdf" --full`，看【5】段：如果同一笔交易的多个词 top 值相差 < 8，但和日期词 top 相差 > 8，就是跨行。

**修复**：用**锚点法**（参考 `ganzhou.py`），不要用逐行解析（`nongye.py`）。

关键三行：

```python
if dist < best_dist:          # 严格小于，不是 <=
    best_dist = dist
    best_idx = i
```

### Q12: 表头文字被 PDF 拆成两行（如"收支类型"→"收支类"+"型"），怎么处理？

**原因**：PDF 排版时表头词跨了两个 y 坐标。

**处理**：`_detect_columns` 里**只匹配主词**（"收支类"），把残字（"型"）放进 `HEADER_TEXTS` 集合，在数据词过滤时丢弃。不要试图拼接表头，那会引入更大复杂度。

```python
HEADER_TEXTS = set(HEADER_KEYWORDS) | {"收支类", "型", "收支类型"}
```

### Q13: 中文长名被拆行后拼接出现空格（`南昌大学第二附 属医院`）

**原因**：默认 `' '.join()` 会在每个中文片段间加空格。

**修复**：拼接时判断相邻字符是否都是全角/中文，是则不空格：

```python
if self._is_wide_char(prev_last) and self._is_wide_char(cur_first):
    result += cur['text']
else:
    result += ' ' + cur['text']
```

### Q14: 解析结果的"总收入/总支出"与 PDF 汇总不符，但抽样核对都没问题，怎么办？

**三步排查**：

**第一步：跑余额连续性校验**

每一笔的 `上一笔余额 + 本笔金额` 应等于 `本笔余额`。任何断点 = 有交易被丢。

```python
import openpyxl
wb = openpyxl.load_workbook("xxx.xlsx", data_only=True)
ws = wb["交易明细"]
rows = list(ws.iter_rows(min_row=2, values_only=True))
print(f"📊 读到 {len(rows)} 行数据")

prev_balance = None
for r in rows:
    date, _, summary, _, amount, balance, *_ = r
    if balance is None or amount is None:
        prev_balance = None
        continue
    if prev_balance is not None:
        expected = round(prev_balance + float(amount), 2)
        diff = round(expected - float(balance), 2)
        if abs(diff) > 0.01:
            print(f"⚠️ {date} {summary} 差 {diff}")
    prev_balance = float(balance)
```

**第二步：看 `len(rows)` 是不是"总笔数 − 表头"**

读错文件是最常见的乌龙。比如实际 893 笔，脚本读到 884 行 → 说明读的是旧文件（885 − 1 表头）。

**第三步：检查是否做了去重**

如果有 `_deduplicate` 按内容指纹，删掉它。参考 [8.7 去重铁律](#87-去重铁律所有插件通用)。

**判断结果**：

- 余额连续性 **0 断点** → 解析 100% 完整，结案
- 有断点 → 断点位置就是漏读位置，去 PDF 对应日期附近找

**历史案例**：2026-11 建行插件因 `_deduplicate` 误杀 8 笔合法交易（相差 7,920 元），通过余额连续性校验一次性定位；v13.2 删除去重后 893 笔与 PDF 完全一致。
